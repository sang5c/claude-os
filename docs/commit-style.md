# 커밋 메시지 컨벤션

## 형식

```
<티켓번호> <type>: <요약>
```

- **티켓이 없으면** 티켓번호를 생략한다: `<type>: <요약>`
  - 이 실습 저장소처럼 Jira 티켓을 안 쓰는 공간은 항상 생략 형태.
  - 실제 개발(Jira 티켓 있음)에서는 `M29CE-1234 feat: ...`처럼 티켓을 맨 앞에 붙인다.

## type 종류

| type | 쓰임 |
|---|---|
| `feat` | 새 기능·산출물 추가 |
| `fix` | 버그 수정 |
| `docs` | 문서·노트·README |
| `refactor` | 동작 변화 없는 구조 개선 |
| `chore` | 설정·이동·정리 등 잡일 |
| `test` | 테스트 추가·수정 |

## 요약 규칙

- 한글로 쓴다.
- 50자 이내, **명사형으로 종결**한다. (예: "추가", "수정", "이동")
- 무엇을 했는지 한눈에 보이게. 모호한 표현("업데이트", "변경") 단독 사용 지양.

## 원칙

- **한 커밋에는 한 관심사만.** 성격이 다른 변경은 나눠서 커밋한다.
- 본문은 사소하면 생략, 복잡하면 "왜"를 한두 줄 덧붙인다.

## 예시

```
feat: 자산 점검에 추이 비교 추가
docs: 1주차 재무 OS 노트를 notes로 분리
M29CE-2600 fix: 적립액 환율 환산 오류 수정
```
